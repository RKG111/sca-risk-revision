# Plan — SCA Risk Revision

## Goal

Context-aware SCA risk assessment: CycloneDX SBOM + codebase → trusted
component–CVE blueprint → agent-gathered evidence → one risk verdict → base and
environmental CVSS. Standalone stack, not Cursor-driven. LLM = Ollama
`qwen2.5-coder:14b`.

## Locked decisions

- **Agent-only evidence.** Probes S1–S4 are LLM agents with tools. There is no
  deterministic re-implementation behind them. An unavailable probe records an
  evidence gap and yields an *inconclusive* verdict, never a "safe" one.
- **One decision site.** `core/policy.py` is the only module that computes
  activation or exploitability. Scoring consumes the verdict, never re-derives it.
- **One of everything else.** One Joern client, one agent loop, one settings
  object, one CVSS value object. Files that would duplicate settings are
  generated by `python -m core.config`.
- **Flat package.** `core/` has no sub-packages; one file per concept.
- Blueprint lookup by `cve_id` + versioned PURL. Exact match only — research
  against one version says nothing about another.
- Blueprints are probe-agnostic cached research JSON under `blueprints/`.
- Agents reach Joern through mcp-joern FastMCP SSE; the service uses Joern's HTTP
  API for its own lookups. Two transports, one server, neither a fallback.
- CR/IR/AR default to High until product criticality is ingested.

## Pipeline

1. Resolve the affected PURL from the CycloneDX `affects` reference
2. Load the `Blueprint` from the store
3. `policy.plan` → activation basis and the probes that can establish it
4. Best-effort Joern CPG import; a CPG sink pre-flight decides whether S1 is worth asking
5. Run probes in dependency waves: S1/S2/S3 together, then S4 if S1 found paths
6. `policy.decide` → one `RiskVerdict`
7. `scoring.adjudicate` → metric answers, with policy clamps applied last
8. `scoring.score` → environmental CVSS → `RiskAssessmentResult`

## Testing

Offline and deterministic. Model replies are scripted per probe, so policy and
scoring can be asserted exactly. `tests/golden/baseline_verdict.json` pins the
decision for the sample fixture and is what proved the rebuild
behaviour-preserving against the pre-rebuild pipeline.

## Out of scope

- Blueprint generation from advisories (NVD/OSV)
- Product-document CR/IR/AR ingestion
- Durable job storage, queueing, auth, multi-process operation
- Chroma / tree-sitter indexing, Semgrep
